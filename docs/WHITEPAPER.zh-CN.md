## 1. 执行摘要

编码智能体会反复重新推导项目已经知道的东西：某个构建标志为何存在、尝试过并否决了哪个修复、什么约束支配某个模块、以及自上周以来发生了什么变化。Veyra 为它们提供持久的、按工作区隔离的**工程记忆**，它具有以下性质：

- **有据可依。** 每条记录都带有指向仓库的证据锚点。无法解析的路径永远不是证据。
- **构造上可信。** 权威级别是一条显式的阶梯（`candidate → derived → canonical`）。只有显式的人类操作才能到达 `canonical`。与当前任务的相似性永远不会赋予权威级别。
- **感知变化。** 新鲜度和信任在读取时针对仓库进行评估，因此漂移的知识会被降级，而不是被静默地提供。
- **仅供参考。** 召回的记忆作为上下文到达，并附带一条常驻提示：它不是仓库真相，也不是指令。

Veyra 作为 DeepSeek Harness 插件发布：纯 ESM，无必需的运行时依赖，每个 DSH 工作区一个 SQLite + FTS5 数据库，以及由独立插件提供的可选结构化代码智能层。

本文分离四个声明层级：**设计目标**（§12.1）、**已实现**（§12.2）、**已验证**（§12.3）和**未验证**（§12.4）。测量问题*“Veyra 是否改善智能体的任务结果？”*得到诚实的回答：尚未测量（§11.4、§13）。

## 2. 问题

上下文窗口是工作集，不是存储。跨会话时，智能体会丢失：

1. **架构理由** —— 为什么用这个数据库、为什么有这个边界、否决了哪种方案以及针对什么症状。
2. **排障历史** —— 已修复缺陷的根本原因、奏效的补救措施，以及不奏效的。
3. **约束** —— “必须支持 Node 22”、“不引入新依赖”、“在迁移落地前不要碰这个模块”。
4. **新鲜度** —— 代码变化后上述哪些仍然成立。

现有的缓解措施各自失效于其中一部分。对话历史是每会话的且无据可依。文档与代码漂移。一个装满 markdown 笔记的文件夹没有生命周期、没有权威模型、也没有读取时信任评估。

Veyra 的立场：工程记忆是一等的、按工作区的、以证据为锚的存储，具有显式的权威级别、验证状态和新鲜度轴，只通过有界、受闸门控制的召回路径投射进智能体上下文，并在每次读取时对照仓库重新检查。

## 3. 设计原则

Veyra 围绕一条信任链组织：

```
Repository Truth + Engineering Memory
    → Applicability and Freshness
    → Trust
    → Agent Context
```

记忆只有在*在此仓库状态下、针对此任务*可信时才有用，即便如此，它也是作为上下文而非指令到达的。

| # | 不变量 | 它排除了什么 | 机制 |
| --- | --- | --- | --- |
| P1 | **观察 ≠ 存储** | 把某事发生过记录得像是真的 | 观察管道只产生候选；噪声过滤器和捕获闸门保留技术侧面 |
| P2 | **候选 ≠ 真相** | 低权威级别记录被召回或被静默提升 | 写入闸门把自动学习推迟到来源之后；`canonical` 需要显式提升 |
| P3 | **相似 ≠ 权威级别** | 良好的词法匹配提升记录的级别 | 权威级别、验证状态、置信度和证据强度独立于相似性评分 |
| P4 | **相似 ≠ 适用** | 接近相关的记录被当作适用 | 适用性来自结构化上下文键和时间边界 |
| P5 | **记忆 ≠ 指令** | 召回的文本被当作命令服从 | 上下文构建器为每个召回块加上非仓库真相提示 |

第六条原则支撑所有五条：**仓库真相**。任何存储记录都不能凌驾于仓库之上，信任在每次读取时重新推导，隐藏矛盾是被拒绝的行为。

## 4. 架构

### 4.1 双脑模型

Veyra 连接两个回答不同问题的层。

| 层 | 持有 | 真相来源 |
| --- | --- | --- |
| **Veyra Memory** | 教训、根本原因、决策、约束、因果链，带证据锚点、验证状态和权威级别 | 累积的、有证据支撑的认知状态 |
| **Code Intelligence** | 符号、文件、调用图、类层次 | 实时的仓库 AST |

它们不可互换。一条记录说“登录函数被重构为使用 JWT”是工程教训。`login()` 今天的调用图是结构真相。Code Intelligence 可以把一条记忆标记为*可能过期*。它从不覆盖记忆，记忆也从不凌驾于代码之上。

### 4.2 记忆服务器

每个插件生命周期一个服务器实例，拥有：

- 一个工作区解析器，
- 一个记忆路由器，
- 每个 DSH 工作区一个私有**记忆房间**，
- 一个共享的**中央记忆库**存储，
- 它们之间一条受治理的提升路径。

它不运行守护进程、定时器或后台任务。每条失败路径都降级为空结果，而不是在智能体循环内抛出异常。

### 4.3 数据流

```
  DSH host — Cordis plugin (src/plugin.mjs)
  session events ──► observe ──► observation ──► write gate ──► derived memory
                                                        │
                                          promotion (explicit only)
                                                        ▼
                                               Central Memories

  ┌───────────────────────────────────────────────────────────────┐
  │  Memory Server  $DSH_HOME/veyra/   (node:sqlite + FTS5)       │
  │  rooms/<roomId>/memory.db   ·   central/memory.db             │
  └───────────────────────────────────────────────────────────────┘
        read-only projections
  ┌──────────────┬──────────────┬──────────────┬─────────────────┐
  ▼              ▼              ▼              ▼
  hybrid recall  local graph    agent context  human surfaces
  tools          src/graph.mjs  system prompt  /veyra, Observatory
                                (fail-closed)  Network Graph
```

本地图是派生的投影，不是第二个存储。

### 4.4 运行时形态

| 属性 | 值 |
| --- | --- |
| 包 | `@lovedolove/veyra`，打包 274.3 kB，52 个文件 |
| 模块系统 | 纯 ESM |
| 必需运行时依赖 | 无 |
| 可选 peer | `@lovedolove/dsh-codebase-memory-mcp`，通过 `src/cbm-bridge.mjs` 加载 |
| Node | `>=22.12.0 <25.0.0` |
| DSH | `>=0.1.2-rc.1 <0.3.0-0` |
| 存储 | `node:sqlite` + FTS5 |

Node 下限有两个原因。`node:sqlite` 首次发布于 22.5。桥接层使用无标志的 `require(esm)` 加载 Codebase Memory 包，该能力从 22.12.0 开始。低于该下限时，桥接层会静默降级，而 `engines` 却声称支持，因此清单选择说真话。

## 5. 核心概念

### 5.1 记录

一条记录是一条工程知识，包含：

- **身份** —— 稳定的 id、种类、范围，
- **内容** —— 标题、正文、标签、可选的因果侧面，
- **证据** —— 指向仓库的锚点，以及笔记和 URI，
- **轴** —— 权威级别、验证状态、置信度，
- **生命周期** —— 状态、保护、关系、历史，
- **来源** —— 如何被捕获以及由什么捕获。

### 5.2 种类

| 种类 | 含义 |
| --- | --- |
| `observation` | 某一轮做了什么，在判断之前 |
| `memory` | 一条持久的工程教训 |
| `knowledge` | 与记忆并存的项目文档，一起被搜索 |
| `evidence` | 带有锚点的已捕获事实 |
| `negative` | 尝试过并被否决的方案 |
| `unresolved` | 一项未结的调查 |

`negative` 和 `unresolved` 是一等的。知道什么失败了、什么仍然未知，对后来的智能体与知道什么奏效同样有价值。

### 5.3 三个轴

| 轴 | 值 | 由什么推动 |
| --- | --- | --- |
| 权威级别 | `candidate` → `derived` → `canonical` | 写入闸门；canonical 需显式人类操作 |
| 验证状态 | `unverified` → `reviewed` → `verified` | 跨会话的重复确认和测试结果 |
| 置信度 | `low` / `medium` / `high` | 捕获和学习时的证据强度 |

只有 `derived` 和 `canonical` 具备召回资格。候选会被存储并可检查，但永远不会被注入。

### 5.4 因果侧面

一条记录可以携带 `symptom → rootCause → remedy → verifiedOutcome`。这些被用于排序和合并决策。

`Root cause:` 侧面决定一条新记录是否重述了已有记录。整体声明比较做不到这一点：在一个真实房间中，真正重复的声明的最佳配对得分为 0.143，低于冲突下限，因为正文长度相差一个数量级。相同的根本原因行得分为 1.000，改写后的得分为 0.727 到 0.909，而真正不同的原因得分至多 0.278。

该规则故障关闭：没有侧面就意味着没有原因重复，并且 `CONFLICT` 判定永远不会被覆盖。

### 5.5 关系

记录之间以 `updates`、`extends`、`derives`、`contradicts` 或 `supersedes` 相互链接。链接在写入时根据传入记录与其最近邻之间的差异派生。矛盾保持可见；解决它是人类的行为。

### 5.6 房间与中央记忆库

| 层 | 持有 | 路径 |
| --- | --- | --- |
| 记忆房间 | 一个 DSH 工作区中学到的一切 | `rooms/<roomId>/memory.db` |
| 中央记忆库 | 显式从房间提升出去的知识 | `central/memory.db` |

房间是 DSH `WorkspaceId`，绝不是文件系统路径。同一仓库上的两个工作区是两个房间。身份无法解析的工作区会故障关闭，而不是猜测。提升是进入中央记忆库的唯一方式。

房间机制之前的 `projects/` 和 `reusable/` 数据库是遗留物：从不读取、写入、迁移、合并或删除。

## 6. 记忆生命周期

### 6.1 捕获

Veyra 观察会话事件。只有真正能修改文件的工具才贡献修改证据。`read`、`grep` 或 `glob` 是活动，绝不是编辑。正文中提到的路径不是被修改的文件，被引用的重定向不是写入。

观察记录文件、符号、测试结果、声明信号和结构化因果侧面。符号需要代码形态：一个标识符后跟参数列表、一个块或一个赋值。恰好包含 `const` 一词的正文不会产生任何东西。

### 6.2 写入闸门

闸门读取文本，而非格式。同一条指令无论以正文、项目符号、编号列表还是复选框项的形式到达，都会被同样判断，因此复选框永远不是绕过它的途径。

判定为 `accept`、`merge`、`drop` 和 `defer`。每个判定连同其原因都被计入一个账本，`/veyra health` 会报告它。

必须接地。`sym:` 笔记不是接地；真实的路径、URI 或锚点才是。这正是阻止一个符号形状的字符串为一条没有锚点的记录设定置信度的原因。

### 6.3 召回

在一轮开始时，相关记录被检索并作为紧凑块注入。每条记录都携带其信任状态。学习和召回可以独立禁用。

当同一记录集在一个工作区中第三次被渲染时，Veyra 切换到紧凑形式：仅标题和警告，正文和证据被丢弃。警告有意保留。一条其锚定文件已改变的记录必须仍然显示其审查警告，而仅标题的形式恰恰把这一点静默掉了。

### 6.4 反馈

`veyra_feedback` 报告应用一条记忆是否奏效。成功会强化记录；失败会记录失败历史。来自召回该记录的那次召回的显式 `generationEventId` 会把结果归属于那次分发。

### 6.5 维护

生命周期操作是显式的：protect、unprotect、invalidate、supersede、forget、tombstone。捆绑的 `memory-maintenance` 技能按请求应用它们，并报告前后状态。健康发现本身永远不是授权。该技能还会报告 `KEEP`、`REVALIDATE` 与 `DEFER`；它们只是报告中的建议，不是存储变更，不会写入任何内容。

## 7. 证据与信任

### 7.1 锚点

证据锚点指向文件、符号、笔记或 URI。仓库之外的路径永远不能成为证据。锚点是让记录日后可检查的东西，而可检查性是把记忆与谣言区分开的东西。

### 7.2 读取时分类

每条被召回的记录都对照当前仓库进行分类：

| 类别 | 含义 |
| --- | --- |
| `trusted` | 锚点可解析；没有任何东西与记录矛盾 |
| `review_required` | 可用，但行动前需核实 |
| `stale` | 锚定的文件已改变；声明可能不再成立 |
| `contradicted` | 另一条记录提出了相反的声明 |
| `insufficient_evidence` | 证据不足：该记录现在无法检查 |

该分类是一个投影。它从不写入，也从不改变权威级别或验证状态。

### 7.3 无法验证不等于过期

当代码智能层缺失时，锚点完全无法解析。Veyra 将新鲜度报告为无法验证，并把记录归类为 `insufficient_evidence`。它不声称路径在仓库之外，也不把记录升级为 `stale`。

这个区分在早期发布中是一个真实缺陷。旧代码捏造了一个原因，而信任层把捏造的原因提升到 `review_required` 之上。一条记录因为一个没人检查过的事实而被降级。

### 7.4 交付

一次 `veyra_recall` 分发记录自己的证据：它返回的记录引用、渲染大小和交付状态。只有工具路径可以是 `DELIVERED`。环境上下文提供者永久保持 `NOT_VERIFIED`，因为 DSH 中没有任何东西能证明模型收到了注入的文本。Veyra 记录存在，而非理解。

## 8. 召回与检索

### 8.1 管道

一次查询产生若干独立信号：

| 信号 | 权重 | 来源 |
| --- | --- | --- |
| 相关性 | 0.32 | FTS5 BM25，带符号和路径加权 |
| 证据 | 0.18 | 锚点强度和解析 |
| 验证状态 | 0.18 | 验证层级 |
| 邻近度 | 0.14 | 范围和上下文邻近度 |
| 新鲜度 | 0.08 | 读取时代码新鲜度 |
| 置信度 | 0.10 | 记录置信度 |
| 语义 | 0.10 | 词元级重叠，而非嵌入 |
| 关系 | 0.04 | 图内聚度 |

各通道以倒数排名融合（`RRF_K = 60`，融合权重 `0.06`）。`goal` 参数以权重 `0.7` 增加亲和力，把排序引向进行中的工作。它是方向，绝不是权威级别。

每个结果都携带分数分解，因此排序可以被解释，而不是被信任。

### 8.2 确定性

没有嵌入、没有向量存储、没有重排器、没有远程服务。这是设计选择，不是待填补的缺口：它让召回可复现、可审计，并且没有网络依赖。代价是改写召回的上限，这在 §13 中说明。

### 8.3 限制处理

`recallLimit` 限制每轮注入多少条记录。`0` 只禁用自动召回上下文，别的什么都不变：工具、命令、Observatory 和已存储的记忆继续工作。这使它成为比较有环境记忆和无环境记忆行为的开关。

## 9. Code Intelligence

结构层是可选的，分为两个独立部分：

| 部分 | 提供 |
| --- | --- |
| `@lovedolove/dsh-codebase-memory-mcp` 插件 | 六个 `cbm_*` 工具和桥接层 |
| `codebase-memory-mcp` 原生二进制 | 索引和答案 |

Veyra 把该插件包声明为可选 peer，并通过 `src/cbm-bridge.mjs` 加载它，这是 `src/` 中唯一命名该包的文件。当包缺失时，桥接层返回一个冻结的存根，Veyra 继续运行，记忆功能完全可用。

Veyra 不注册任何 `cbm_*` 工具。这是有意的边界：两个插件注册相同的工具名是加载顺序竞争，且失败是静默的。这些工具属于拥有桥接层的插件。

降级该依赖换来的是加载安全，而非移除。pnpm 默认安装可选 peer，而列出该插件的 profile 会保留它。

存在但加载失败的包，与缺失的包不同。Veyra 对前者警告一次，对后者保持沉默，因为干净的安装不应发出警告。

## 10. 安全与隔离

| 关注点 | 保证 |
| --- | --- |
| 仓库写入 | 无。Veyra 从不写入用户的仓库 |
| 机密 | 每条写入路径在持久化前脱敏 |
| 脱敏深度 | 形态层级加上一个经过验证的层级：支付卡（Luhn）、IBAN（ISO 13616 mod-97）、美国 SSN |
| 工作区隔离 | 房间以 `WorkspaceId` 为键，绝不以路径为键；无法解析的身份故障关闭 |
| 跨工作区泄漏 | 只有显式提升才能到达中央记忆库 |
| 记忆中的提示注入 | 敌意信号被检测并标记，从不被服从 |
| 敌意召回内容 | 渲染前清洗 |
| 失败行为 | 降级为空结果；绝不向智能体循环抛出 |

该插件也拒绝成为代码的真相来源。这既是安全属性，也是设计属性：一条能凌驾于仓库之上的记忆将是一个注入面。

## 11. 验证

### 11.1 测试套件

1173 个测试、13 个套件在 CI 中于 Node 22 和 24 上运行，同时还有一个运行时依赖守卫和一个打包检查。套件覆盖生命周期、矛盾处理、损坏、隔离、脱敏、检索排序、上下文渲染、插件生命周期和 Code Intelligence 边界。

### 11.2 基准测试

`docs/BENCHMARK.md` 报告 45 个维度上的 29 个测试，由 `test/m15-benchmark.test.mjs` 针对专门构建的夹具运行。测试框架打印它所断言的同一张表，因此文档和运行不会彼此漂移。每个数字都是一个比率，其中 `1` 是安全结果，每一行都携带其证据。

这是机制验证。它证明机器在夹具上按规范运行。它不测量任务结果。

### 11.3 跨项目演练

两个真实存储在 2026-09 和 2026-10 端到端演练了系统：一个 Web 应用项目和一个遗留仓库入门。它们产生了漂移案例和自动召回噪声观察，后者塑造了后续工作。

那些运行使用了房间机制之前、以路径为键的存储布局。该布局已不存在，因此这些运行是**关于行为的历史证据**，而不是关于存储的当前状态证据。它们按此被报告。

### 11.4 尚未测量的内容

带 Veyra 的智能体是否比不带 Veyra 的智能体更好地完成真实工程任务。这需要一项配对实验，具有匹配的任务、隔离的实验臂和预先注册的指标。协议及其阻塞项记录在 `docs/research/` 中，而先前的尝试返回了零结果或不确定的结果，这些被记录下来而非掩埋。

### 12.3 已验证

- 1173 个测试在 Node 22 和 24 上通过。
- 运行时依赖守卫在每个交付文件上通过。
- 打包检查产生一个有效的 52 文件 tarball。
- 45 维基准重新断言它自己的表。
- `recallLimit: 0` 产生空上下文，别的什么都不变。
- 缺失的 Codebase Memory 包可以加载、降级，并让记忆继续工作。
- 损坏的安装警告一次；干净的安装保持沉默。
- 降级的层报告无法验证的证据，而不是捏造的原因。
- 原因重复到达合并决策，而不仅仅是差异。

### 12.4 未验证

1. **任务结果效用。** 不存在经测量的配对任务结果。
2. **入门覆盖率。** 遗留入门一趟能捕获真实代码库持久知识的多少比例，尚未测量。
3. **自动召回噪声率。** 在一个会话群体中观察到了噪声；比率尚未测量。
4. **通用性。** 验证一直是在一台主机上的 DSH 相邻项目上进行的。
5. **长期存储行为。** 失败不对称特性已通过夹具验证；它们在多年老存储上的行为是推断的。
6. **改写上限。** 在没有嵌入的情况下，大型存储中词法加重叠的上限尚未测量。

## 13. 已知限制

1. **仅确定性检索。** 没有嵌入、向量存储、重排器、LLM 评判器或远程服务。
2. **基于夹具的基准。** 机制验证，而非结果测量。
3. **锚点粒度。** 文件、符号和 URI 级别。URI 锚点在读取时不重新解析。
4. **入门不对称。** 一趟遗留处理会写入许多候选和少量已验证记录；召回资格因显式提升步骤而滞后。
5. **受人类约束的步骤。** 验证、规范提升、矛盾解决和遗忘受保护记录在设计上需要人类。
6. **主机要求。** Node `>=22.12 <25` 上的 DSH 插件。
7. **仅供参考的记忆。** 智能体可能忽略召回的记忆。价值主张受遵从度约束，这正是配对实验重要的原因。
8. **交付上限。** Veyra 能证明一次分发发生了。它不能证明模型读取了文本。

## 16. 术语表

- **权威阶梯** —— `candidate → derived → canonical`。只有 derived 和 canonical 具备召回资格；canonical 仅通过显式人类提升。
- **候选** —— 自动捕获的观察。被存储、可检查、从不自动召回。
- **因果侧面** —— 记录上的结构化 `symptom`、`rootCause`、`remedy` 或 `verifiedOutcome` 字段。
- **中央记忆库** —— 只能通过显式提升到达的共享存储。
- **DEFER** —— 写入闸门的“尚未”判定，带一个原因字符串。
- **交付** —— 一次召回分发发生的证据。绝不是模型读取了它的证据。
- **记忆房间** —— 一个工作区的私有存储，以 DSH `WorkspaceId` 为键。
- **RRF** —— 跨检索通道的倒数排名融合（`K = 60`）。
- **墓碑** —— 被遗忘记录的终态生命周期标记。
- **无法验证** —— 因代码智能层不可用而无法检查的新鲜度。与过期不同。
- **写入闸门** —— 把观察变成持久记忆、或拒绝这样做的决策点。
